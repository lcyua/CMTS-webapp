# 분리 저장소와 운영 경계

2026-11-13 코드 기준입니다. Worker `3c140c5b-1b47-4859-a625-e9a75af1708f`는 배포됐고 health v2·서버 설정 응답을 확인했습니다. 운영 계정으로 인증한 분리 조회와 실제 데이터 마이그레이션 완료는 아직 확인하지 않았습니다. 아래 동작은 구현·로컬 검사 결과이며 운영 완료 선언이 아닙니다. 구현은 [state-repository.ts](../worker/state-repository.ts), 백업·복구 절차는 [OPERATIONS.md](../OPERATIONS.md)를 따릅니다.

## 문서 구조

기본 문서는 `classes/{classId}/private/state`입니다. 회원·역할·상점·운영 설정·배치 등과 `_storage` 메타데이터를 유지합니다. 아래 10개 배열의 미이전 행은 기본 문서에 남고, 이전된 행은 별도 문서에 저장됩니다.

`audits`, `events`, `attempts`, `lots`, `inbox`, `payouts`, `requests`, `exams`, `quizzes`, `notices`

경로의 `B`는 `_storage.generation`이 없으면 `classes/{classId}`, 있으면 `classes/{classId}/storageGenerations/{generation}`입니다.

| 경로 | 용도 |
| --- | --- |
| `B/history_{table}/{id}` | 해당 표의 원본 행 |
| `B/members/{uid}/history_{table}/{id}` | `record.uid`가 있는 행의 학생별 조회 사본 |
| `classes/{classId}/commandReceipts/{hash}` | 세대와 별개로 유지하는 중복 요청 영수증 |
| `classes/{classId}/migrationBackups/{hash}` | 첫 이전 직전 기본 문서의 불변 사본 |

행 문서는 `{record, sequence}`를 저장합니다. 원래 `record.id`를 보존하고, 별도 문서 ID는 16자리 시각과 16자리 시퀀스를 결합합니다. 과거 행의 ID가 겹쳐도 서로 덮어쓰지 않습니다. 퀴즈에는 활성 문제의 날짜인 `publishedDate`, 공지에는 `importantActive` 조회 필드를 추가합니다. lot 잔액·신청 상태·알림 읽음은 원본 행과 학생별 사본을 함께 갱신합니다.

`_storage.version=1`은 저장 형식입니다. API의 `clientVersion=2`와 구분합니다. 메타데이터에는 다음 항목이 있습니다.

- `generation`, `nextSequence`, `revision`: 활성 세대와 변경 순서
- `counts`, `ownerCounts`, `activeNotices`: 원본 행 수·개인별 행 수·활성 공지 수. 조회 사본은 중복 집계하지 않습니다.
- `unreadInbox`: 개인별 전체 미읽음 수
- `balances[uid][expiresAt]`: 만료 시각별 사용 가능·예약 포인트 요약
- `gates`: 회원별 변경 요청 예산

학생 응답에는 개인별 요약과 공개 공지만 제공하고 내부 메타데이터는 제거합니다. 화면용 요약 lot은 실제 FIFO 원장이 아닙니다. 포인트 명령은 필요한 실제 lot을 조회해 계산합니다. 만료됐고 예약이 없는 요약 버킷은 제거하지만 과거 lot 문서는 삭제하지 않습니다.

## 원자적 이전과 중복 방지

저장소의 학급 업무 변경은 기본 문서의 `updateTime` 사전조건으로 직렬화합니다. 명령에 필요한 과거 행을 읽은 뒤 기본 문서·변경 행·조회 사본·영수증·선택적 푸시 작업을 한 commit으로 반영합니다. 충돌하면 다시 읽어 최대 8회 시도합니다.

첫 변경에서 `_storage`가 없으면 원래 기본 문서 전체를 `{state, sourceUpdateTime, createdAt}`로 백업합니다. 백업 ID는 원본 `updateTime`의 SHA-256이며 `exists=false`로 생성합니다. 백업과 첫 이전이 같은 commit에 들어가므로 부분 이전이나 백업 덮어쓰기를 허용하지 않습니다. 이 사본은 정기 외부 백업을 대신하지 않습니다.

기존 행은 명령당 최대 80개를 추가로 이전하며, commit 여유가 적으면 줄입니다. 미이전 행은 그대로 남습니다. 새 행과 변경된 행은 별도 문서로 저장합니다. 조회는 미이전 행과 분리된 행을 함께 다룹니다.

영수증 키는 `SHA256(JSON.stringify([actor, key]))`입니다. 같은 요청은 다시 반영하지 않고 입력이 달라지면 거부합니다. 과거 두 감사 ID 형식에서도 영수증을 복원합니다. 월별 지급 표식과 당일 답안을 별도로 조회하므로 기본 배열이 비어도 재지급·재응시를 허용하지 않습니다.

## 조회·인덱스·무료 쿼터

조회는 컬렉션 경로로 소유자를 제한하고 단일 필드 조건을 사용합니다. 현재 필드는 `record.id`, `record.status`, `record.date`, `record.month`, `record.expiresAt`, `record.reserved`, `record.active`, `publishedDate`, `importantActive` 및 `__name__`입니다. 범위 조건은 해당 필드와 `__name__`를 내림차순으로 정렬합니다. 기본 자동 단일 필드 인덱스를 사용하도록 작성했으며 별도 복합 인덱스 배포는 요구하지 않습니다. 운영 프로젝트의 인덱스 면제 설정이나 실제 인증 쿼리 성공까지 확인한 결과는 아닙니다.

Firestore Rules는 계속 모든 클라이언트 직접 읽기·쓰기를 거부합니다. 이 저장소 변경을 위해 Rules를 완화하거나 배포할 필요가 없습니다. 서버가 인증·활성 회원·역할·소유권을 검사합니다.

`clientVersion=2` 조회는 포인트·미읽음 요약, 대기 신청, 학생의 당일 문제·답안, 교사의 최근 문제 20개, 활성 공지 20개와 중요 공지 20개의 합집합을 가져옵니다. 전체 포인트 lot이나 과거 기록을 매번 읽지 않습니다. 과거 기록은 별도 화면에서 페이지로 조회합니다. 기존 Hosting UI의 `clientVersion!=2` 호환 경로는 일부 이력 표마다 최근 50개를 추가로 읽으므로 새 프런트보다 읽기 비용이 큽니다.

학생은 본인의 포인트·답안·알림·신청 이력과 활성 공지만 조회합니다. 감사·지급·과거 문제 정의는 교사 범위입니다. 학생의 당일 문제 응답에서 정답·해설을 제거합니다.

주요 경계는 다음과 같습니다.

| 항목 | 한도·동작 |
| --- | --- |
| 이력 페이지 | 기본 25개, 요청당 1~50개 |
| 완전성이 필요한 업무 조회 | 최대 4,096행; 초과하면 부분 계산 대신 거부 |
| commit | 최대 500 writes; 조회 사본·영수증·백업·푸시도 포함 |
| 기본 문서 | JSON 700,000바이트 초과 시 원자 거부 |
| 회원 변경 요청 | 회원당 1분에 30회; 완료 영수증 재시도는 추가 반영 없음 |
| 백업·복구 | 파일 크기·일관성·세대 전환 경계는 OPERATIONS.md 참고 |

사본은 쓰기·저장량을 늘리고 영수증과 이력은 계속 쌓입니다. 경합·자료량·구형 UI 조회에 따라 비용이 달라집니다. 장기간 무료 CPU·요청·Firestore 쿼터를 보장하는 수치는 아니며 운영 실측이 필요합니다. 기본 문서에 남는 운영 설정도 700KB 제한을 받습니다.

커서는 소유자·표·세대·마지막 문서에 묶입니다. 미이전 행이 있는 동안에는 기본 문서 버전도 묶어, 변경 시 처음부터 다시 조회하도록 합니다. 이전 완료 후에는 다른 학급 활동으로 커서를 무효화하지 않지만 복구로 세대가 바뀌면 무효화합니다. 정렬은 문서 ID를 사용해 수정된 신청 시각 때문에 페이지가 중복되거나 누락되지 않게 합니다.

## 배포·복구·보존

Worker의 구형 조회 호환 경로를 먼저 배포하고 `clientVersion=2` Hosting을 이어서 배포합니다. health 성공이나 배포 성공만으로 운영 데이터 이전 완료를 보고하지 않습니다. 실제 인증 조회·권한·커서·변경·충돌과 무료 쿼터를 별도로 확인해야 합니다.

`_storage`가 생긴 뒤에는 배열 전체가 기본 문서에 있다고 가정하는 과거 Worker로 단순 롤백하지 않습니다. 분리 저장 형식을 지원하는 서버를 유지하거나 운영 절차로 완전한 논리 백업을 복구해야 합니다. 기본 문서만 내보내거나 덮어쓰면 이력을 빠뜨릴 수 있습니다.

운영 백업은 활성 세대의 원본 행과 미이전 행·전역 영수증을 일관된 스냅샷으로 모읍니다. 복구는 새 세대에 원본·사본을 준비한 뒤 원래 기본 문서 버전이 유지됐을 때만 포인터를 전환합니다. 이전 세대는 남기고 영수증은 합쳐 중복 반영을 막습니다. 준비 중 실패한 세대는 활성화하지 않습니다.

이 구현은 과거 원장·영수증·이전 백업·비활성 세대를 자동 삭제하지 않습니다. 보존·삭제 일정은 승인된 운영 정책과 OPERATIONS.md로 관리합니다. 유료 TTL, 결제 연결, 기존 18명 계정·PIN 재발급이나 기존 학생 비밀번호 조회를 이전 절차에 추가하지 않습니다.
