## 서버 설정

- 공개 VAPID 키는 사용자 제공 후 P-256 공개 키로 검증했으며 `wrangler.jsonc`의 `WEB_PUSH_VAPID_PUBLIC_KEY`에 보관합니다. 인증된 `readState.pushConfig`가 `enabled`, 공개 키, 기본 수신 상태만 제공하고 클라이언트 `configure()`가 적용합니다. 이후 키 변경은 Hosting 재빌드 없이 서버 설정으로 반영할 수 있습니다. 서버 키·PIN·pepper를 공개 설정에 넣지 않습니다.
- Worker 설정: `PUSH_ENABLED=true`. 기존 전용 런타임 서비스 계정에 FCM 발송용 `roles/firebasecloudmessaging.admin` 권한과 FCM API 사용이 필요합니다. 앱 자체는 권한·API·결제 설정을 자동 변경하지 않으며 운영자 도구의 명시적 적용이 필요합니다. 별도 FCM 서버 비밀키를 클라이언트에 넣지 않습니다.
- Worker scheduled 이벤트에서 `dispatchPush`를 호출합니다. 기본값은 실행당 1개 작업, 계정당 최대 5기기입니다. 측정 후에도 `maxJobs`는 최대 5로 제한합니다. 1분 주기의 기본 처리량은 하루 최대 1,440개 알림 작업입니다. 작업은 순서대로 처리하므로 기기 상태와 대기량에 따라 지연될 수 있습니다. 운영 중 CPU와 Firestore 무료 쿼터를 관찰하며 장기 한도 검증은 별도입니다.
- `public/sw.js`가 `/push-worker.js`를 가져와야 합니다. 같은 서비스 워커를 PWA와 Messaging 토큰에 사용합니다. 별도 Firebase 서비스 워커를 루트 범위에 등록하지 않습니다.

## 서버 연결

`/pushDevice`는 기존 Firebase ID token 서명·철회·활성 Auth 사용자 검사 후에만 처리합니다. 서버의 학급 상태에서 현재 UID의 활성 membership을 확인한 뒤 `updatePushDevice(store,classId,uid,state,data,env.PUSH_ENABLED==='true')`를 호출합니다. 등록은 `action:'register',deviceId,token`, 현재 기기 해제는 `action:'unregister',deviceId`, 계정 전체 기기 해제는 `action:'unregisterAll'`입니다. 호출자의 레지스트리만 수정하며 토큰은 반환하지 않습니다.

기기 토큰은 `classes/{classId}/pushUsers/{SHA256(uid)}`에 계정당 최대 5개를 보관합니다. 학급 상태·학생 응답·감사 입력·브라우저 자체 localStorage에 넣지 않습니다. `pushTokens/{SHA256(token)}`의 소유자 기록으로 동일 토큰을 다른 계정에 동시에 연결하는 것을 거부합니다. 등록 commit은 현재 학급 상태의 updateTime도 verify하여 비활성화와 경합한 등록을 거부합니다. 90일 동안 갱신되지 않은 등록·토큰 소유자 기록과 FCM의 `UNREGISTERED` 응답은 제한된 수량씩 제거합니다. 클라이언트는 개인 수신 거부가 없고 브라우저 권한이 이미 허용된 기기를 로그인·복원 시 자동 연결합니다. 일반 새로고침은 중복 등록을 생략하고 6시간 이상 지난 연결은 갱신합니다. 권한 미결정·거부 상태에는 자동 팝업을 띄우지 않습니다.

도메인 명령 적용 전 inbox ID 집합을 보관한 뒤, 저장소의 같은 commit 안에서 `preparePushWrites` 결과를 함께 저장합니다. 제어 문서 `pushControlPath(classId)`도 같은 사전조건으로 읽고 써야 합니다. 명령과 큐 생성이 분리되면 중간 실패 때 알림을 놓칠 수 있으므로 별도 후처리로 큐를 생성하지 않습니다. 한 명령당 최대 32개·대기 최대 256개를 큐에 넣고 넘치는 건수는 제어 문서의 `dropped`에 남깁니다. 앱 내 알림 원본은 유지합니다.

## 전달·개인정보·로그아웃

잠금 화면에는 고정된 제목·본문만 보냅니다. 학생 이름·포인트·교사 작성 본문은 전송하지 않습니다. 누르면 같은 출처의 앱만 열며 실제 내용은 인증 후 조회합니다. 앱이 보이는 동안에는 시스템 알림 대신 앱에 새로고침 이벤트를 보냅니다.

전달 전 현재 학급 membership·수신 설정과 분리 저장된 inbox 기록의 소유자·읽음 상태를 다시 확인합니다. scheduled 호출은 `isUserActive(uid)`를 기존 Auth 사용자 조회에 연결하여 Auth에서만 비활성화한 사용자도 제외합니다. 인증 서버 일시 오류는 비활성 계정으로 간주하지 않고 lease 만료 후 재시도합니다. 읽은 알림, 비활성·수신 거부 계정, 24시간이 지난 작업은 보내지 않습니다. 전송 실패는 최대 5회 제한된 지수 대기로 재시도하고 완료·실패 기록은 7일 후 제한된 수량씩 지웁니다. 성공이 확인된 기기에는 같은 작업을 다시 보내지 않습니다. 응답 확인 전 네트워크가 끊기면 중복 수신 가능성이 있으며 FCM topic과 알림 tag로 중복 표시를 줄입니다. 정확히 한 번 전달을 보장하지 않습니다.

로그아웃과 계정 전환은 **Firebase signOut/signIn 전에** `push.cleanup()`을 실행합니다. 서비스 워커의 로컬 수신 허용을 먼저 꺼서 오프라인에서도 표시를 차단하고, 서버의 현재 기기 등록과 Firebase 토큰을 정리합니다. 수신 설정 확인은 최대 1초·네트워크 정리는 최대 3초만 기다려 로그아웃이 연결 실패 때문에 막히지 않게 합니다. 지연된 토큰 삭제가 새 토큰을 지우지 않도록 새 등록은 이전 정리 작업이 끝난 뒤 실행합니다. 앱의 ‘내 알림 수신’을 끄면 `push.disableAll()`이 현재 기기의 동의 여부와 관계없이 서버 전체 기기를 해제합니다. 다른 탭의 로그아웃 이벤트에는 `push.pause()`를 호출합니다. 로그아웃·계정 전환은 수신 의사를 끄지 않고 기기 연결만 정리합니다. ‘이 기기 알림 끄기’를 명시적으로 선택하면 개인 기기 수신 거부를 저장합니다. 권한 미결정 기기에는 로그인 후 ‘알림 허용’ 버튼을 표시하고, 버튼을 누를 때만 브라우저 권한을 요청합니다. ‘나중에’는 해당 세션의 안내만 숨기고 수신 거부로 저장하지 않습니다.

코드는 로컬 모의 전송으로 검사했으며 실제 학생에게 시험 메시지를 보내지 않았습니다. 실서비스 발송은 활성화했고 교사 본인 기기 테스트를 안내했습니다. 인증된 발송·조회 CPU, 실제 기기 수신, Android/iOS 홈 화면 설치와 iOS 수신은 별도 확인이 필요합니다.

## 운영자 권한 설정

현재 Cloud 작업 환경에는 Google 프로젝트 관리 인증이 없으므로 운영자 PC의 정상 `gcloud` 로그인 또는 Google Cloud Shell에서 다음 도구를 실행합니다. Firebase CLI 인증정보를 추출하거나 다른 SDK로 전달하지 않습니다.

```sh
python3 configure-push.py
python3 configure-push.py --apply --confirm wooriban-2027
```

저장소 경로는 `scripts/configure-push.py`이며, 전달 패키지에서는 루트에 있습니다. 기본 실행은 현재 gcloud 계정·프로젝트 IAM·서비스 계정 메타데이터만 읽습니다. 기존 `roles/datastore.user`와 `roles/firebaseauth.viewer`를 모두 가진 계정이 정확히 하나인지, 같은 프로젝트의 활성 계정인지 확인합니다. 모호하면 자동 선택하지 않습니다. 변경 모드는 FCM API 두 개를 활성화하고 해당 기존 계정에 `roles/firebasecloudmessaging.admin` 하나만 추가합니다. 기존 역할·학생 계정·PIN·결제 설정·서버 키를 변경하지 않습니다. 실제 설정 완료와 화면 배포 확인 후 `PUSH_ENABLED=true`로 배포합니다.

## 본인 기기 수신 확인

교사는 알림내역의 ‘테스트 알림 받기’로 현재 본인 등록 기기 한 대만 확인할 수 있습니다. 별도 수신자나 토큰을 입력하지 않으며 다른 학생에게 보내지 않습니다. 교사당 60초에 한 번, 전체 전송 제한은 10초입니다. 서버는 현재 활성 상태·수신 설정·등록 정보를 원자적으로 검증하고, 실패해도 제한 창을 유지합니다. 권한·API·VAPID·만료 토큰 오류는 비밀값 없이 안전한 안내로 반환합니다.

명시적인 테스트는 앱이 열려 있어도 고정된 시스템 알림을 표시합니다. 일반 전경 알림은 기존대로 앱 새로고침 이벤트만 보내며, 로그아웃·수신 거부 시에는 둘 다 표시하지 않습니다. 서버의 성공은 FCM 접수 확인이며 실제 기기 표시까지는 사용자가 확인해야 합니다. 자동 테스트 발송은 없습니다.
